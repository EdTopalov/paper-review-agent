# M2: working loop and first evaluation

A **task** reviews one paper. The **agent** chooses searches, page reads, and when
to submit; the **baseline** reviews the full paper in one model call. Both return
an absolute score from 0 to 1, a summary, evidence-backed observations, and open
questions using the same OpenAI model and scoring criteria.

The **score** expresses the model's judgment of the paper's research and discussion
value, considering contribution, evidence, limitations, and intellectual depth.
The anchors are 0.00 for little supported value, 0.25 for limited value or serious
weaknesses, 0.50 for useful, defensible work, 0.75 for a substantial, well-supported
contribution, and 1.00 for exceptional work. Scores are independent of the other
papers in a batch. They are not probabilities or validated human quality ratings.

## Implementation and changes from M1

We built the loop and baseline, froze 20 paper-text snapshots, measured both,
then added page-specific observations and citation repair after inspecting failures.
The agent has five reading actions and eight model decisions. Empty results and
tool errors become observations; transient API errors receive one retry.

Changes from the [original plan](M1.md):

- Use 20 public, versioned papers instead of private reading-club references:
  reliable reference scores were unavailable, so numerical score accuracy is deferred.
- Freeze pypdf text rather than inspect page images: reproducible inputs are ready,
  but figures and damaged table layouts remain outside the implemented scope.
- Use one inexpensive OpenAI backend and one package to keep execution simple;
  multiple providers, external retrieval, and extra reading for close scores are deferred.
- Run one paired comparison per version instead of five repetitions. Repeated
  evaluation is supported, but score variance remains unmeasured.

## Evaluation and results

**Completion** means the workflow returns an accepted review. The agent also
requires quotations to match observed text on the cited page; the baseline returns
its review even when citations are wrong. Thus completion is not an accuracy score.
A **verified citation** matches source text, allowing whitespace and limited PDF
formatting differences. Verification catches edited or invented quotations and
wrong page references, gives the agent concrete repair feedback, and lets a reader
locate the evidence behind a judgment. It makes reviews easier to audit, but does
not establish that a quotation supports the claim or that the paper is good.

We checked final outputs and action paths: citation matches, valid arguments,
budgets, and call accounting. A separate **evidence audit** asked the model whether
each claim follows from the paper. These methods measure textual/operational
correctness and provisional claim support, respectively; neither validates scores.

Saved results use `gpt-6-luna` on the same 20 papers, once per method. Means include
failed attempts; audit costs are separate. Inference plus audits cost $0.247373.

The agent's missing review exhausted its quotation-repair budget. Baseline
completion includes citation errors. Eight agent runs recovered from rejected
submissions; three empty searches and one invalid page range were handled.
Citation compliance is partly enforced by the agent's acceptance rule, not an
independent measure of understanding.

The audit labeled 72/75 agent observations and 78/80 baseline observations supported.
Its judgments are uncertain: it even [rejected a numerical improvement while citing
40.0% versus 30.1%](../runs/m2-integrated-20261026/baseline-r1/T01/README.md#evidence-audit).
Human adjudication is needed before claiming better assessment quality.

## Open evaluation problems

**Scores cluster and the criteria remain vague.** Ratings occupy a narrow part of
the scale, and several papers tie, making close rankings hard to justify. It is
difficult to explain consistently what makes a contribution good, evidence strong,
or a limitation serious across different papers. The current instructions leave
these trade-offs underspecified. Clustering could reflect the rubric, model
tendencies, or similar papers in the sample; it does not establish which is at
fault. Human worked examples and repeated ratings are needed to interpret small
differences reliably, while allowing ties.

**We do not yet have a validated quality dataset.** The 20 frozen papers provide
reproducible inputs, but no human-agreed scores or claim-support labels. They are
a convenience sample of well-known, openly licensed ML papers the model may
already know, with no human-curated coverage of weak or borderline work. Figures
and table layouts are missing, and private reading-club notes remain provisional.
Citation checks and same-model audits cannot fill these gaps. We need diverse,
human-reviewed cases with reasons and disagreements, plus separate development
and unseen test sets; the existing inputs should stay frozen for comparisons.

## Diagnosed failures

- [Wrong page](../data/failures/F02.json), [step 5, event 25](../runs/archive/failures/agent-r1/T06/README.md#step-5-submit_review--accepted):
  a multi-page read lost page provenance. Separate page objects and wrong-page
  diagnostics address this.
- [Edited quotation](../data/failures/F03.json), [step 5, event 25](../runs/archive/failures/agent-r1/T13/README.md#step-5-submit_review--accepted):
  the model paraphrased evidence and cited the next page. Require an exact quote
  and let the model repair it before acceptance.
- [Repair loop](../data/failures/F05.json), [step 6, event 30](../runs/m2-integrated-20261026/agent-r1/T17/README.md#step-6-submit_review--citation_validation_failed):
  four rejected submissions exhausted eight decisions. Repeated rewriting and
  conservative PDF hyphen handling interacted; reread/copy the passage or drop
  the unresolved observation. This does not establish that the claims were false.

The linked cases preserve exact model inputs and tool observations for later
next-action tests. M1's predicted evidence and parsing problems occurred;
topic bias, abstract hype, and score variance remain unmeasured.

## Inspect or rerun

Start with the [readable results](../runs/m2-integrated-20261026/README.md); task
pages show reviews, decisions, and expandable tool details. Each task has one
structured trace containing its result and optional audit. Original logs remain
in the [archive](../runs/archive/README.md). Formatting was changed offline without
new model calls; these numbers describe the archived source, not a fresh evaluation.

After [installation](../README.md#installation), use a fresh output directory:

```shell
paper-review eval --out runs/my-comparison --workers 3
paper-review audit --experiment runs/my-comparison --workers 3
paper-review check runs/my-comparison
```
