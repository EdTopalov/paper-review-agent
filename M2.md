# M2: bounded paper reading and first evaluation

The implemented agent independently assesses a paper using the M1 rubric and
absolute `[0,1]` score anchors. It chooses reading tools, their arguments, and when
to submit its review. Both the adaptive agent and one-call baseline completed the
same frozen 20-paper sample. These are first measurements, not validated estimates
of agreement with expert paper-quality ratings.

## Setup and entry point

Tested with CPython 3.12 on Windows. Install the recorded dependencies in an isolated
environment. The lock includes the development dependencies used for verification.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-m2.txt
.venv\Scripts\python.exe -m pip install --no-deps -e .
Copy-Item .env.example .env
```

Put a working `OPENAI_API_KEY` in `.env` locally. `.env` is ignored by Git and its
values override inherited environment variables. `OPENAI_MODEL` defaults to
`gpt-6-luna`; an explicit `--model` overrides it. No real keys are committed.

The commands below use the installed `paper-review` executable. On Windows use
`.venv\Scripts\paper-review.exe` unless the environment is activated. On Linux or
macOS use `.venv/bin/paper-review` and replace the setup interpreter path with
`.venv/bin/python`; `cp .env.example .env` replaces `Copy-Item`.

```powershell
paper-review models
paper-review verify --sample data/eval/tasks.jsonl
paper-review review data/eval/papers/T01.json --task-id T01 --out runs/scratch/example --model gpt-6-luna
# Local PDF input is also supported:
paper-review review path/to/paper.pdf --out runs/scratch/local-paper --model gpt-6-luna
```

`models` lists model IDs accessible to the key's project. `verify` performs no API
calls and should print `{"verified_tasks": 20, "distinct_papers": 20}`. A review
prints its structured result and writes `trace.jsonl` and `result.json` under the
chosen directory. Successful results contain `status: "ok"`, a score, summary,
2–4 observations with quotes/page numbers, and unresolved questions. Reusing a
single-run output directory is refused so an earlier trace is not overwritten.
Model availability depends on the API project; the tested key exposes GPT-6 Luna.
The official model page currently gives the same name as its default snapshot;
there is no dated identifier available here to guarantee future model immutability.

## Run the evaluation

```powershell
paper-review eval --sample data/eval/tasks.jsonl --out runs/my-comparison --model gpt-6-luna --workers 3
paper-review audit --sample data/eval/tasks.jsonl --experiment runs/my-comparison --model gpt-6-luna --workers 3
python scripts/verify_traces.py runs/my-comparison
python scripts/rank_results.py runs/my-comparison/agent-r1 --out runs/my-comparison/ranking.json
```

The first command runs 20 agent assessments and 20 baseline assessments. The audit
is a separate, additionally billed set of 40 model calls. Results are not expected
to match byte-for-byte: requests use low reasoning effort without a deterministic
seed. `--variant agent` or `--variant baseline` selects one configuration;
`--limit 2` is a smoke run and does **not** meet the 20-task evaluation requirement.
`--repeats 5` supports the repeated experiment proposed in M1.

An evaluation writes `experiment.json`, per-task traces/results, `summary.json`,
`summary.md`, and `mechanical.jsonl`. Auditing adds `audits/` and
`audit_summary.json`. Trace verification adds `trajectory_checks.jsonl` and
`trajectory_summary.json`. Ranking sorts absolute scores without rescaling them;
equal scores use task ID only as a deterministic display tie-break. Processing
errors are listed separately and never converted to low research-quality scores.

For offline inspection of the submitted measurements:

```powershell
paper-review summarize runs/m2-20261026
python scripts/verify_traces.py runs/m2-20261026
python -m pytest -q
```

`summarize` and trace verification use saved files, not model calls. A resumed
evaluation retains existing results only when sample, code digest, and settings
match; otherwise choose a new output directory. The submitted experiment predates
the CLI encoding and audit-index fixes described below, so use a **new directory**
to run the current code rather than resuming it. Its evaluated source is preserved
under [`runs/m2-20261026/source`](runs/m2-20261026/source), with the digest in
[`experiment.json`](runs/m2-20261026/experiment.json). Agent policy and common rubric
were not changed after seeing these results.

## Agent loop and error handling

The controller passes metadata and PDF page 1 to the model. At every iteration the
model chooses one of `search_paper(query, reason)`, `read_pages(start, end, reason)`,
or `submit_review(reason, review)`. Searches return snippets with page numbers;
reads return at most three consecutive PDF pages. The model may finish early.
Five reading actions are allowed, counting unsuccessful reads/searches. After
that only submission is available. A separate decision-call bound prevents an
infinite loop. Submission is a model-selected function call, not a scripted final
stage or forced series of page reads.

Invalid page ranges, malformed arguments, empty searches, and tool exceptions
become structured observations. The model can revise its action. Transient API
errors receive at most one retry; permanent API errors are recorded without
echoing credential-bearing exception messages. Failures leave a result and trace.
The offline tests explicitly exercise invalid arguments, invalid page ranges,
empty searches, API retries, permanent API failure, early stopping, and budgets.
These scripted tests are not counted as live evaluation results.

Every agent/baseline trace records model requests/responses, the chosen tool and arguments,
the model's brief stated purpose, tool observations, errors/retries, final review,
settings, document hash, source digest, dependencies, token usage, cost, and timing.
Events have monotonic sequence numbers and are flushed immediately. The reasons
are observable action rationales, not claimed access to private chain-of-thought.
Read JSONL by iterating physical lines: paper text can contain Unicode separators.

## Frozen data and evaluation method

The [sample manifest](data/eval/tasks.jsonl) contains 20 distinct, versioned papers;
each task is a complete paper assessment. The [sample documentation](data/eval/README.md)
explains selection and limitations. The 20 text snapshots preserve 566 PDF pages,
author attribution, CC BY 4.0 licenses, source URLs, PDF hashes, extraction version,
and snapshot hashes. Frozen page text is the complete tool environment. The agent
and baseline receive the same underlying text; the baseline receives all of it in
one call. Neither sees reviewer notes, reference scores, or judge verdicts.

The five-paper reading-club pilot remains development material and is ignored by
Git because publication permission is unresolved. It is not counted as 20 tasks,
treated as approved labels, or passed to the model. No private club notes are part
of this public sample. `scripts/freeze_sample.py` downloads versioned CC BY papers
and refuses to overwrite a different freeze; downloads are optional for running
the committed snapshots.

Two methods are reported separately:

1. **Mechanical checks:** schema-valid completion, score range, valid PDF page,
   and exact quotation containment after whitespace normalization. We also check
   recorded tool arguments, reading budgets, call accounting, and stop decisions.
   These checks are reproducible but do not establish semantic support.
2. **Provisional LLM evidence audit:** a separate call receives the review and full
   frozen paper, assigning each observation `supported`, `overstated`,
   `unsupported`, or `uncertain`. It judges claims, not the numeric quality score.
   The audit uses the same inexpensive model in a separate context. It is neither
   independent expert judgment nor human-adjudicated accuracy; correlated errors,
   missed problems, and overly strict judgments remain possible.

Evaluation covers task-level outputs and basic trajectory validity. There is no
single prescribed reading path, and we do not claim to measure optimal tool
selection. Per-observation audit findings are retained for inspection.

## Results

Run on 26 October 2026 using `gpt-6-luna`, low reasoning effort, standard service,
five reading actions, 4,000 maximum output tokens per call, and three workers.
One repetition per configuration was completed. The frozen sample/prompt existed
before these runs. There was no prompt tuning on the resulting failures.

| Measure | Adaptive agent | One-call full-paper baseline |
|---|---:|---:|
| Schema-valid completion | 20/20 | 20/20 |
| All quotations match cited pages exactly | 12/20 | 8/20 |
| Matching quotations / all observations | 66/80 (82.5%) | 59/80 (73.75%) |
| Mean reading actions per task | 4.00 | 0 |
| Mean model/API calls per task | 5.00 | 1.00 |
| Mean end-to-end latency per task | 11.19 s | 6.38 s |
| Mean API cost per task | $0.001791 | $0.003364 |
| Total inference cost, 20 tasks | $0.035822 | $0.067278 |

Costs use returned input/output, cache-read, and cache-write token counts, including
reasoning output and retries when present. Prices are recorded in traces; these
are estimates, not invoices. Latency includes local parsing/validation and retries,
excluding time waiting in the worker queue. Evaluation audit costs are separate.
All 40 traces passed the trajectory checks. There were **23 empty search results**
across the 20 agent runs; every run recovered by reading pages and completed.
Most queries were keyword bundles, while the tool implemented literal matching:
valid argument types did not imply effective tool selection. No tool exceptions
occurred in the live sample. Additional recovery cases use offline controlled tests.

The model audit judged 77/80 agent observations supported and 3 overstated; it
judged 78/80 baseline observations supported and 2 overstated. All observations
were judged supported in 17/20 agent reviews and 18/20 baseline reviews. It assigned
no `unsupported` or `uncertain` verdicts. **These are the judge's opinions, not
validated success rates.** The audit cost $0.069497 for agent outputs and $0.069844
for baseline outputs. Recorded inference plus audit cost totals approximately
**$0.24244**, excluding the small development/probe calls.

The loop used fewer input tokens despite more calls, so it was cheaper in this
run; it was slower. The measurements do not show a semantic-quality advantage over
the baseline. Exact quotation compliance improved, but this metric rejects harmless
PDF ligatures and line-break hyphenation as well as genuine wrong-page citations.
For example, T01's `significantly` quotation differs from the extracted `signiﬁcantly`.
Literal mismatch is not automatically an invented claim. Conversely, an existing
quote can still support an overstatement, as F01 illustrates.

Eight audits initially failed solely because the model returned an unambiguous
1-based observation list while the parser expected 0-based indices. The
[initial summary](runs/m2-20261026/audit_summary-initial.json) and original error
records are retained. `scripts/repair_audit_indices.py` normalized those saved
indices without further API calls or any changed verdicts/explanations, appending
repair events to the traces. The current parser handles both conventions and has
regression tests. A Windows console Unicode-print issue was also fixed; saved
UTF-8 reviews and the agent policy were unaffected.

## Four annotated failed decisions

These are actual live agent runs. All four ended with a structurally valid review;
the failures concern evidence interpretation, citation fidelity, or a wasted search. Each case has
the exact final-decision request, frozen tool observations, observed action, and a
proposed next-action condition under [`data/failures`](data/failures). A candidate
M3 policy can replay the saved prefix without redownloading papers or running tools.

| Case | Exact decision | Problem and plausible cause | Proposed repair |
|---|---|---|---|
| [F01: Reflexion](data/failures/F01.json) | T02, step 5, `submit_review`, [trace event 25](runs/m2-20261026/agent-r1/T02/trace.jsonl#L25), observation 2 (zero-based) | The model turns a requirement for a termination heuristic and binary reward into a claim that task-specific machinery restricts transfer. The paper allows more specific heuristics but does not establish the asserted restriction. This is an interpretive overstatement, not a disproved research concern. | State the requirement as a scope condition or qualify the transfer concern as an open question; retrieve supporting evidence before making the stronger assertion. |
| [F02: SWE-bench](data/failures/F02.json) | T06, step 5, `submit_review`, [trace event 25](runs/m2-20261026/agent-r1/T06/trace.jsonl#L25), observation 1 | The 4.8% result is on PDF page 5 but is cited as page 6. The model read pages 5–6 together at step 3 and lost page provenance. The result itself is supported. | Preserve page identity per excerpt and validate quote/page pairs before accepting submission; use page 5. |
| [F03: Self-RAG](data/failures/F03.json) | T13, step 5, `submit_review`, [trace event 25](runs/m2-20261026/agent-r1/T13/trace.jsonl#L25), observation 0 | The source sentence is on page 3, includes `(Table 1)`, and is submitted as an edited quotation from page 4. The model summarized a multi-page observation while constructing evidence fields. Post-submission checks expose but do not repair the error. | Copy the exact page-3 sentence, including its parenthesis, or retrieve a different exact passage; feed invalid citation checks back as recoverable observations. |
| [F04: ReAct search](data/failures/F04.json) | T01, step 1, `search_paper`, [trace event 5](runs/m2-20261026/agent-r1/T01/trace.jsonl#L5) | `ALFWorld WebShop results success rate Table 1` is a keyword bundle. The literal-phrase matcher finds nothing. The tool description failed to specify these semantics; the model then recovered with page reads, using one of three reading actions on the empty search. | Describe literal search explicitly or implement token-based retrieval; test the next action against a tool contract with clear query semantics. |

F02 and F03 were checked directly against frozen text. F01 also agrees with the
provisional model audit, but interpreting how categorical the wording is remains
a judgment call. The strict-format false alarms and audit-index bug are additional
evaluation failures, not fabricated bad agent runs. Do not turn every failed
literal quote check into a claim of hallucination. F04 demonstrates a recoverable
tool-contract failure that simple schema/trajectory-validity checks do not catch.

## M1 connection and remaining uncertainty

| M1 choice | M2 treatment and reason |
|---|---|
| Independent absolute scores and common anchors | Kept; deterministic sorting is separate from scoring. |
| Adaptive bounded reading | Kept with model-selected search, read, and submit actions. |
| PyMuPDF parsing and page/figure inspection | Used BSD-licensed pypdf for a small text-only implementation; image inspection is deferred and extraction limitations are explicit. |
| Multiple providers, close-score rereading, external search | Deferred to finish the measured loop and harness within the deadline. |
| Five held-out papers | Replaced by 20 distinct frozen paper tasks to satisfy M2; private pilot material stays separate. |
| Score MAE against reference ratings | Deferred because no defensible reference scores exist. No numeric gold labels were invented from comments or model tone. Evidence audits do not substitute for score calibration. |
| Five repeated runs | Harness supports them; only one pass was run under the deadline. No run-to-run score variance, confidence claim, or significance claim is reported. |
| Evidence-backed assessments | Checked mechanically and with a separately labeled model audit, including identified limitations of both evaluators. |

The M1 failure map is updated as follows:

- **Abstract hype hides weak support:** not established by this sample; agent reads
  went beyond abstracts, but no controlled weak-paper gold set exists.
- **Parsing corrupts evidence:** extraction artifacts affected exact-match checks;
  misleading table interpretation was not separately established.
- **Topic/type bias:** not measured. The sample is mostly agent-related empirical
  work, with one survey, and cannot validate fairness across disciplines/types.
- **Score fluctuation or weak-batch inflation:** unmeasured with one repetition and
  no gold scores. Many well-known papers may already be in model training data.
- **Close-score review wastes reads:** deferred feature, so not tested here.
- **Plausible assessment cites insufficient support:** observed in F01; evidence
  location/fidelity failures additionally occurred in F02 and F03.
- **Reference model bias:** no reference-score model was used. The evidence judge
  is provisional and may share biases with the assessed model; agreement is not
  independent confirmation.

Newly observed beyond the original map: keyword-search semantics mismatched the
model's queries, and the auditor's indexing convention mismatched its parser.

For M3, keep the current frozen inputs and failure prefixes, add human adjudication
and numerical reference-score uncertainty, and test citation recovery before
adding more tools. Sources and licenses are listed in [THIRD_PARTY.md](THIRD_PARTY.md).
