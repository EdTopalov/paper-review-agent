# M2: integrated paper-review agent and measured failures

The unified implementation uses OpenAI, incorporates the team's citation-checking
work, and evaluates the same frozen 20-paper sample as the first prototype.
**The integrated agent completed 19/20 tasks; the one-call baseline completed
20/20.** The failed agent run is preserved and diagnosed. Completion and citation
fidelity are reported separately from provisional judgments of review quality.

## Setup and documented entry point

Tested in a fresh CPython 3.12 virtual environment on Windows. From the repository
root:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-m2.txt
.venv\Scripts\python.exe -m pip install --no-deps -e .
Copy-Item .env.example .env
```

Enter your working `OPENAI_API_KEY` in `.env` locally. The file is ignored by Git;
its values override inherited environment variables, including revoked keys.
`OPENAI_MODEL` defaults to `gpt-6-luna`; `--model` explicitly overrides it. The
professor-provided key was checked and supports this inexpensive model. Another
project may expose different models: `paper-review models` lists accessible IDs.
Unknown model pricing is reported as unavailable, never invented.

Use `.venv\Scripts\paper-review.exe` for the commands below on Windows unless the
environment is activated. On Linux/macOS use `.venv/bin/python` for installation,
`.venv/bin/paper-review` for execution, and `cp .env.example .env` for the copy.

```powershell
.venv\Scripts\paper-review.exe verify --sample data/eval/tasks.jsonl
.venv\Scripts\paper-review.exe review data/eval/papers/T01.json --task-id T01 --out runs/scratch/example --model gpt-6-luna
# A local PDF is also supported:
.venv\Scripts\paper-review.exe review path/to/paper.pdf --out runs/scratch/local-paper --model gpt-6-luna
```

`verify` makes no API calls and should report 20 verified tasks and 20 distinct
papers. `review` writes `trace.jsonl` and `result.json`, then prints JSON. A completed
result has `status: "ok"`, an absolute `[0,1]` score, summary, 2–4 observations with
quotes and page numbers, and unresolved questions. A failed result has
`status: "error"` and a diagnostic; it is not assigned a low research-quality score.
Single-run output directories cannot be reused, preserving earlier traces.

The package lives only in `src/paper_review`. The updated `test.ipynb` is an optional
example calling the same runner, with no stale output or separate Gemini backend.
The CLI is the reproducible entry point; Jupyter is not a dependency.

## Run the evaluation

```powershell
.venv\Scripts\paper-review.exe eval --sample data/eval/tasks.jsonl --out runs/my-comparison --model gpt-6-luna --workers 3
.venv\Scripts\paper-review.exe audit --sample data/eval/tasks.jsonl --experiment runs/my-comparison --model gpt-6-luna --workers 3
.venv\Scripts\python.exe scripts/verify_traces.py runs/my-comparison
.venv\Scripts\python.exe scripts/rank_results.py runs/my-comparison/agent-r1 --out runs/my-comparison/ranking.json
```

The first command makes 20 agent and 20 baseline attempts. The separately billed
audit judges completed reviews only: 19 agent plus 20 baseline reviews in the
submitted integrated run. Ranking sorts completed papers by absolute score without
rescaling; equal scores use task ID as a display tie-break. Errors are listed
separately. `--limit 2` is useful for a smoke run but does not satisfy M2's 20-task
requirement. `--repeats 5` supports M1's planned repeated comparison.

Outputs include experiment settings/source digest, frozen evaluated source,
per-task traces/results, mechanical results and summaries, optional model audits,
trajectory checks, and ranking. Use a fresh `--out` for a new experiment. Resume
retains existing results only when settings, sample, source digest, and recorded
revision match. Stochastic output is not expected to reproduce byte-for-byte.

Offline inspection needs no API key or calls:

```powershell
.venv\Scripts\paper-review.exe summarize runs/m2-integrated-20261026
.venv\Scripts\python.exe scripts/verify_traces.py runs/m2-integrated-20261026
.venv\Scripts\python.exe -m pytest -q
```

The isolated dependency environment passed **41 tests**. GitHub Actions runs the
same offline tests, frozen-hash verification, and trace checks on Linux. Attributes
preserve the exact bytes of frozen JSON/JSONL across Git line-ending settings.

## Integration and genuine agent control

The team commit [39d760f](https://github.com/EdTopalov/paper-review-agent/commit/39d760f2e47b66d074de34397101dcc66e53ead1)
remains in history. We retained its exact/normalized/wrong-page citation concepts
and page-specific reading design, combined with the working OpenAI Responses
runner, CLI, dataset, and evaluation harness. The root-level duplicate package was
removed; execution has one package and model backend.

The model starts with metadata and PDF page 1. It chooses `search_paper`,
`read_pages`, or `submit_review`, including arguments and a brief stated purpose.
It can stop early. `read_pages` returns 1–3 page objects, each carrying its own page
number and truncation flag. Search explicitly matches a literal keyword/phrase,
not a bundle of web-search keywords. This addresses the 23 empty searches in v1.

Code executes and validates the chosen actions rather than choosing a fixed
sequence. Five reading actions are permitted; unsuccessful reads/searches count.
At most eight model decisions are allowed. With no reading budget left, only
submission is offered. Invalid arguments, page ranges, empty results, and tool
exceptions are observations the model can recover from. Transient API failures
receive at most one retry; permanent failures remain recorded.

The integrated `submit_review` validates citations and whether the quoted text was
actually exposed in page reads, snippets, or the opening page. Invalid submissions
return per-citation diagnostics; the model chooses to reread, change the quotation,
or otherwise repair its review. It must finish within the existing decision
budget. The one-call baseline has no repair loop and receives the full frozen text.
Its citation errors remain in its output for evaluation.

Every decision and observation is retained: requests/responses, tool arguments,
visible action reasons, validation errors, retries, final answer/error, source and
paper hashes, dependencies, model settings, tokens, costs, and timing. JSONL events
are numbered and flushed. Read physical JSONL lines, since paper text may contain
Unicode separators. The reasons are visible action rationales, not private
chain-of-thought. No trace contains authentication headers or keys.

## Combined citation checker

| Category | Treatment |
|---|---|
| Exact source substring | Verified. |
| Whitespace-only differences | Verified; also counted in the original strict metric. |
| PDF ligatures, soft hyphens, canonical Unicode, preserved line-end hyphens | Verified as `normalized`, separately from strict matching. |
| Quote found on another page | `wrong_page`, with matching page numbers. |
| Matching requires deleting a line-end hyphen | `hyphenation_ambiguous`, with candidate pages; not silently verified. |
| No match under accepted rules, empty quote, or invalid page | Reported explicitly; never accepted as a valid citation. |

Unlike unrestricted compatibility normalization, `x²` cannot become `x2`.
The checker preserves case, decimal points, signs, and meaningful hyphens. For
example, `1.0` differs from `10`, and `re-cover` is not automatically `recover`.
Tests cover these adversarial cases. The conservative rule can reject harmless
PDF word wrapping: that uncertainty is deliberate and visible, and contributed to
the T17 failure. A verified quote proves text correspondence, not support for the
claim or usefulness of the assessment.

## Frozen sample and evaluation methods

The [manifest](data/eval/tasks.jsonl) freezes 20 distinct, versioned paper tasks.
[Page-text snapshots](data/eval/papers) preserve 566 PDF pages, attribution, source
URLs, CC BY 4.0 licenses, original PDF hashes, parser version, and snapshot hashes.
Both configurations use exactly this saved text with the unchanged common M1
rubric (`m2-v1`). The integrated action policy/checker are separately versioned
`m2-v2` / `m2-citations-v2`. No live downloads occur during evaluation.

The selection predates evaluation and covers agents, tools, coding, retrieval,
reasoning, context evaluation, and one survey. It is a convenience sample of
well-known, openly licensed 2022–2024 ML papers, not a representative sample of all
research quality or disciplines. The model may know these papers from training.
Figures and layout are unavailable in this text-only milestone environment.
The five-paper private reading-club pilot remains separate development material,
ignored by Git; its provisional annotations are not gold labels or model inputs.
See the [data documentation](data/eval/README.md).

We use two methods:

1. **Mechanical task/trajectory checks:** schema-valid completion, score bounds,
   strict quotations and integrated citation categories; plus argument validity,
   reading budgets, call accounting, and recorded stop decisions. We log first
   submission checks and rejection counts to expose how much the validation gate
   changes the final output. These are operational/textual checks, not semantic
   accuracy, and no unique optimal reading path is prescribed.
2. **Provisional model evidence audit:** a separate call sees the assessment and
   full frozen paper, grading every observation as supported, overstated,
   unsupported, or uncertain. It evaluates the final claims, not score calibration.
   The same inexpensive model is used in a fresh context, with no configuration
   label. Shared biases and mistaken verdicts remain possible; this is not human
   gold. Failed reviews are not silently removed from completion denominators.

## Integrated results

Run on 26 October 2026, `gpt-6-luna`, low reasoning effort, standard service,
4,000 maximum output tokens per call, five reading actions, three workers, and one
repetition per configuration. No model/action-policy changes were made after this
run. Its [source snapshot](runs/m2-integrated-20261026/source) and
[experiment metadata](runs/m2-integrated-20261026/experiment.json) are preserved.

| Measure | Integrated agent | One-call baseline |
|---|---:|---:|
| Completed attempts | 19/20 | 20/20 |
| All citations verified, out of 20 attempts | 19/20 | 7/20 |
| All quotes satisfy whitespace-only strict matching | 18/20 | 6/20 |
| Verified quotations in completed reviews | 75/75 | 65/80 |
| First submissions with all citations verified | 11/20 | 7/20 |
| Mean reading actions per attempt | 3.90 | 0.00 |
| Mean model/API calls per attempt | 5.55 | 1.00 |
| Mean latency per attempt | 15.32 s | 7.14 s |
| Mean API cost per attempt | $0.002155 | $0.003382 |
| Total inference cost | $0.043107 | $0.067640 |

Eight agent runs recovered after rejected submissions. There were 14 rejected
submissions overall, three empty search results, and one invalid page-range
observation (T09, recovered). T17 exhausted eight decisions after four rejected
submissions; one reading action remained unused. All 40 traces passed the basic
trajectory checks, including this recorded bounded failure.

Citation compliance is partly **enforced by the agent's acceptance gate**; 75/75
among completed reviews is not an independent success estimate. The first-submission
count, extra calls, and failed task expose its cost. The baseline's accepted output
schema does not enforce source fidelity. The agent was cheaper here because it
sent less paper text, but was slower. These measurements do not establish a
semantic-quality advantage for adaptive reading.

Costs include returned input/output, cache-read and cache-write token counts,
including reasoning output and retries where present. Rates and usage are in each
trace; estimates are not invoices. Mean cost and latency include the failed task.
Latency includes local work and retries, excluding queue time. The API returned no
billing-uncertain errors in this experiment. Model names may drift over time; the
API provides `gpt-6-luna` as its default identifier rather than a dated snapshot.

The separate audit judged 72/75 agent observations
and 78/80 baseline observations supported, assigning
three and two overstatement verdicts respectively. It judged every observation
supported in 16/19 completed agent reviews and
19/20 baseline reviews. The failed agent task was
not audited. Audit costs were $0.066801 and
$0.069825; inference plus audit totaled **$0.247373**.

These are the judge's opinions, not validated review accuracy. A concrete evaluator
failure appears in the [T01 baseline audit](runs/m2-integrated-20261026/audits/baseline-r1/T01/audit.json):
it says ReAct does not improve WebShop success over Act while quoting 40.0% versus
30.1%; the frozen paper's page-8 table gives those values. Some other verdicts also
penalize qualified open questions. Thus the audit needs human adjudication and
cannot confidently rank the workflows' semantic quality. No verdicts were manually
flipped to improve reported numbers.

## Initial experiment and honest comparison

The [initial v1 experiment](runs/m2-20261026) is retained unchanged: 20/20 completion
for both configurations, 12/20 strict-citation agent reviews versus 8/20 baseline
reviews, and mean costs $0.001791 / $0.003364. Its evaluated source is archived.
The initial audit had eight 1-based-index parsing failures; original error records
and the [initial summary](runs/m2-20261026/audit_summary-initial.json) remain saved.
Those indices were normalized from the existing responses without model calls or
changed verdicts. The integrated parser has regression coverage for both conventions.

The [offline v1 rescoring](runs/m2-citation-rescore.json) applies the combined checker
to the same old outputs without changing them or making model calls. It verifies
all citations in 14/20 agent reviews and 8/20 baseline reviews. The teammate's
broader checker accepted 16/20 and 9/20 in the comparison, but also folds case and
removes internal hyphens; the integrated checker intentionally accepts fewer
ambiguous differences. Rescoring measures evaluator differences, not agent gains.
The integrated live run changed page observations, tool descriptions, and recovery
behavior together; it is not an ablation isolating one cause of improvement.

## Five annotated failed decisions, retained for M3

Each [failure fixture](data/failures) stores its trace pointer, exact model-request
prefix with frozen tool observations, observed action, root-cause hypothesis,
and a next-action condition. M3 can replay the prefix with tools stubbed from the
saved observations. Multiple valid repairs are allowed; no single reading path is
assumed. F01–F04 are initial live runs; F05 is the integrated bounded failure.

| Case | Exact trace decision | Problem, plausible cause, and next repair |
|---|---|---|
| [F01: Reflexion](data/failures/F01.json) | v1 T02, step 5, `submit_review`, [event 25](runs/m2-20261026/agent-r1/T02/trace.jsonl#L25), observation 2 (zero-based) | A termination/reward interface requirement is expanded into a categorical transfer restriction. The quoted text does not establish that restriction. Qualify it as an open question or retrieve stronger support. This remains an interpretive judgment; matching text cannot settle it. |
| [F02: SWE-bench](data/failures/F02.json) | v1 T06, step 5, `submit_review`, [event 25](runs/m2-20261026/agent-r1/T06/trace.jsonl#L25), observation 1 | A correct 4.8% result from page 5 is cited as page 6 after a concatenated 5–6 read. Preserve per-page provenance and return wrong-page diagnostics before acceptance; both are implemented in v2. |
| [F03: Self-RAG](data/failures/F03.json) | v1 T13, step 5, `submit_review`, [event 25](runs/m2-20261026/agent-r1/T13/trace.jsonl#L25), observation 0 | A page-3 sentence loses its internal `(Table 1)` and is cited as page 4. The underlying summary is supported, but the quotation is edited. Copy the actual text/page or retrieve another passage; v2 can reject and repair this. |
| [F04: ReAct search](data/failures/F04.json) | v1 T01, step 1, `search_paper`, [event 5](runs/m2-20261026/agent-r1/T01/trace.jsonl#L5) | A web-style keyword bundle is sent to literal search, giving an empty result. The tool contract was underspecified. V2 describes literal matching explicitly and gives an empty-result hint; empty searches fell from 23 to 3 across the two runs, without isolating causality. |
| [F05: failed quote repair](data/failures/F05.json) | v2 T17, step 6, `submit_review`, [event 30](runs/m2-integrated-20261026/agent-r1/T17/trace.jsonl#L30); final rejection at event 42 | The model repeatedly labels edited strings exact, rather than rereading or retaining only the 2–4 verified observations. Conservative hyphenation handling contributes; four rejections exhaust eight decisions. Inspect/copy the flagged source or drop the unresolved observation while recording uncertainty. The failure is not proof that the substantive claims are false. |

F02/F03 are directly checked against frozen text. F01's categorical scope is
judgment-dependent. F05 demonstrates the cost of a conservative checker interacting
with poor repair decisions. The contradictory audit explanation is an additional
evaluator failure, not an invented bad agent run or adjudicated gold label.

## M1 changes and updated failure map

Kept: independent absolute scores, fixed anchors without dimension weights,
model-selected bounded reading, deterministic ranking, the full-paper one-call
baseline, tracing, and per-task calls/cost/latency. The package/backend are unified
around OpenAI; the teammate's work is preserved through the integration history.

Changed or deferred:

- Five held-out papers became 20 distinct frozen tasks. Private notes remain a
  separate development pilot, with no approved numerical labels.
- PyMuPDF/image inspection became a pypdf text-only environment for this milestone.
  Snapshots are never silently re-extracted when comparing variants.
- Multiple providers, URL ingestion, close-score rereading, and external search are
  deferred to keep the implemented loop and harness understandable and measured.
- Score MAE is deferred because no defensible numerical reference scores exist.
  The model audit does not replace score calibration, and no gold scores were
  inferred from paper popularity or reviewer tone.
- Five stochastic repetitions are supported but not completed per variant. No
  run-to-run variance, statistical significance, or confidence claim is made.

Observed against the M1 failure map: plausible but insufficiently supported
assessments (F01), PDF/citation fidelity problems (F02/F03), and extraction-sensitive
validation (F05). Abstract-hype susceptibility, topic/type bias, score inflation,
and repeated-run score variance remain unmeasured. Close-score review is deferred,
so its wasted-read risk was not tested. Reference-score bias is unmeasured because
there are no reference scores; evidence-judge errors are concretely demonstrated.
New failures include underspecified search semantics and the initial audit-index
mismatch. The next useful work is human adjudication, robust evidence repair, and
frozen-prefix decision tests before adding more tools.
